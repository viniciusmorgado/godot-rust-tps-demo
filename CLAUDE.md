# Oxide Godot — operational guide

Port of the Godot TPS Demo (GDScript) to Rust via godot-rust/gdext. The rules that govern the
project are in `.specify/memory/constitution.md` — this file covers only *how* to operate.

## Layout

```
oxide-godot/                 repo root (git, Spec Kit, this file)
├── oxide-godot/             Godot 4.7 project (TPS demo + extension.gdextension)
└── oxide_godot_core/        Cargo workspace; crate `oxide_godot` (cdylib) in oxide_godot_lib/
```

Untouched reference of the GDScript original: `../oxide_godot_origins/` (outside the repo).

## Toolchain

- Godot 4.7.2 stable: `/usr/bin/godot.x86_64` (there is no `godot` on PATH — use the full path).
- Stable Rust (cargo/rustc 1.98). `godot = "0.5.5"` declared in `[workspace.dependencies]`;
  members inherit it with `{ workspace = true }`. Do not pin an `api-4-x` feature nor change the
  crate version: the template is generated by an external tool that always picks the latest stable.
- gdext feature `experimental-threads` enabled since Milestone D (`Cargo.toml`): without it the
  codegen omits `ResourceLoader::load_threaded_request/get_status/get` (godot-codegen
  `special_cases.rs:83-86`), which the menu uses for the loading bar. No other feature.
- `Cargo.lock` stays out of git (template decision).

## Work cycle

1. Edit Rust in `oxide_godot_core/oxide_godot_lib/src/`.
2. `cd oxide_godot_core && cargo build` — mandatory after **every** Rust change; it is the debug
   build that replaces `target/debug/liboxide_godot.so`, referenced by the `.gdextension`
   (`reloadable = true`, an open editor hot-reloads it).
3. Bind the Rust class to the node by editing the `.tscn` as text (equivalent to the editor's "Change Type"):
   - on the line `[node name="X" type="Base" ...]`, replace `type="Base"` with `type="RustClass"`;
   - remove that node's `script = ExtResource("N")` line;
   - remove the orphaned `[ext_resource type="Script" ... path="res://.../x.gd"]`;
   - delete the corresponding `.gd` and `.gd.uid`.
4. Validate headless (always from `oxide-godot/oxide-godot/`):
   - re-import / check the extension: `/usr/bin/godot.x86_64 --headless --import --path .`
     (the line `Initialize godot-rust (...)` confirms the library loaded);
   - run a scene: `/usr/bin/godot.x86_64 --headless --path . path/to/scene.tscn`.
   Pre-existing errors of the upstream demo at import (`Cannon_Charge already exists`,
   missing `doorsimple_d.png`, `surfaces.is_empty()`) are known and are not regressions.
   In headless `main.tscn` the set `Initializing already initialized RID` /
   `Parameter "mem" is null.` / 3× `Parameter "m" is null.` may appear intermittently (a race
   between the level loading in a sub-thread and the dummy renderer) — it is not a regression if
   it disappears on a second run (specs/004 research §E.2).

## Port conventions (v1)

- One Rust class per `.gd` script, with the **same base** as the script (`CharacterBody3D`,
  `MultiplayerSynchronizer`, `Camera3D`, ...). `class_name Player` → `struct Player`.
- The name of a registered class MUST NOT coincide with any script identifier of the `.gd` files
  that still exist (`const`, `class_name`, top-level `var`) nor with an engine class: GDScript
  rejects the whole script ("The member X shadows a native class"). Check before naming:
  `grep -rhoE '^(const|class_name|var|@onready var|@export var) [A-Za-z_]+' oxide-godot --include='*.gd' | sort -u`
  (real case: `RedRobot` collided with `const RedRobot` in `level.gd:6` → the class became `EnemyRobot`).
- Names of methods exposed with `#[func]` identical to the GDScript ones (`_on_door_body_entered`,
  `hit`, `explode`, ...) so the `.tscn` `[connection]`s, `has_method()` and `.rpc()` keep working.
- `@export var` → `#[export] var`; `@onready var x = $Path` → `#[init(node = "Path")] x: OnReady<Gd<T>>`;
  `signal x` → `#[signal] fn x()`.
- Direct translation, no refactoring/abstraction (Principle I of the constitution). Noticed
  improvements go to the v2 backlog, never into v1 code.

## API notes (gdext 0.5.5)

- `get_tree()` returns `Gd<SceneTree>` directly (no `Option`).
- Access to the base node: `self.base()` / `self.base_mut()`.
